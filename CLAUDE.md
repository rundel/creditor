# creditor

R package that wraps the [`loro`](https://github.com/loro-dev/loro) Rust crate to expose Loro CRDT documents to R. Exploratory. The build and binding layout mirrors the sibling [`q2r`](../q2r) package.

## Architecture

### Rust

- [src/rust/src/lib.rs](src/rust/src/lib.rs) exposes thin `#[extendr]` functions named `loro_*_impl`, tagged `/// @noRd` so they are not R-exported. Fallible calls return `extendr_api::Result`, which surfaces as an R error.
- Two pointer types cross the boundary: `ExternalPtr<LoroDoc>` for documents and `ExternalPtr<loro::Container>` for every container handle. Using the `Container` enum (rather than one pointer type per container) keeps a single handle type; each function unwraps the variant it needs via `as_text` / `as_map` / `as_movable_list` / `as_counter` / `as_tree` and errors on a mismatch. `LoroList` and `LoroMovableList` share method names but no trait, so the shared `loro_list_*` functions dispatch over both with the `with_list!` macro. Child containers are created through the `new_child!` macro, which is the one place that lists the creatable kinds.
- A handle is returned to R by `container_ref` as `list(kind, ptr)` with class `creditor_container_ref`. Functions that can return either a plain value or a child container (`loro_map_get_impl`, `loro_list_get_impl`) go through `value_or_container_to_r`; the class is what lets R tell the two apart, since plain values never carry one. Text, map, list, movable list, counter, and tree are supported; an unknown container type falls back to its deep value on read.
- [src/rust/src/container_value.rs](src/rust/src/container_value.rs) produces container and document values (`container_to_r`, `doc_to_r`) by walking the handles, not by converting `get_deep_value()`. A `LoroValue` no longer records which container each part came from, so a tree node's 0-based `index` could not be told apart from a map entry named `index`; the walker knows the type and emits tree nodes with 1-based `index` and `NA` root parents. Items are collected from `for_each` before any child is read, so no Loro iteration is open while another container is accessed. The `deep` flag switches child containers between expanded contents and id strings. Diffs and subscription events still use `get_deep_value()` for inserted child containers (they are built while Loro is emitting an event, where reading other containers is not safe), so a tree nested inside a diff insert keeps Loro's raw form.
- [src/rust/src/value_to_r.rs](src/rust/src/value_to_r.rs) converts a `LoroValue` into nested R lists (map keys sorted for stable output; `I64` becomes an integer when it fits and is not `NA_integer_`, else a double).
- [src/rust/src/r_to_value.rs](src/rust/src/r_to_value.rs) is the inverse, for values stored with `map_set` / `list_insert`: `NULL` and `NA` become null, length-one atomic vectors become scalars, other unnamed vectors and lists become lists, named ones become maps, raw becomes binary, and anything with a class attribute is rejected. Zero-length vectors are handled before any slice is taken, because building a slice from an empty R vector's data pointer panics (and aborts R) in debug builds.
- [src/rust/src/delta.rs](src/rust/src/delta.rs) converts between `Vec<TextDelta>` and the R delta shape (a list of ops, each a named list with one of `retain` / `insert` / `delete` plus optional `attributes`). Delta counts are Unicode code points, like every other text index.
- Rich text: mark keys must be present in the document's `StyleConfigMap` or `mark` fails with "Style configuration missing". `loro_doc_config_text_style_impl` always starts from `StyleConfigMap::default_rich_text_config()` (bold, italic, underline, link, highlight, comment, code) and overlays the caller's keys, because `config_text_style` replaces the whole map and there is no getter to merge with. Keys containing `:` are rejected up front since `StyleConfigMap::insert` panics on them.
- Cursors cross as `Cursor::encode()` bytes and are resolved with `LoroDoc::get_cursor_pos`. `LoroText::get_cursor` does not reject an out-of-range position (it silently returns an end cursor), so the range check lives in R. List cursors (`loro_list_cursor_impl`) work on both list types, but Loro cannot resolve a cursor on a movable-list element once that element has been moved (`get_cursor_pos` fails with "Cannot find relative position"); this is documented and pinned by a test.
- [src/rust/src/history.rs](src/rust/src/history.rs) converts a `DiffBatch` (text, list, and map diffs; child containers by deep value; other types as `unsupported`) and the change log (`travel_change_ancestors` from the oplog frontiers, sorted by lamport then peer) to R. The diff's type field is emitted as `type_` because `type` is a Rust keyword inside `list!`; R renames it. Versions for history cross as `Frontiers::encode()` bytes; a change's frontiers is the id of its last op.
- `doc_frontiers()` reports `state_frontiers()` (what the document is showing), which differs from the oplog frontiers while detached. A detached document is read-only (detached editing is not enabled).
- [src/rust/src/events.rs](src/rust/src/events.rs) implements subscriptions as queues, not direct callbacks. Loro's subscriber closure converts each event to an R object and pushes it onto an `EventQueue`; R later drains the queue with `loro_subscription_take_impl` and calls the user's function. This keeps R code (which can error, or re-enter Loro) from ever running inside a Loro commit or import. `EventQueue` has `unsafe impl Send + Sync` because Loro requires it of subscribers while `Robj` is neither; this is sound only because every Loro call happens on R's main thread. Do not introduce threads without revisiting it.
- The ephemeral store is an `ExternalPtr<loro::awareness::EphemeralStore>`, independent of any document. Its two subscription kinds reuse `QueuedSubscription`. Inside `loro_ephemeral_get_impl` the pointer is first re-borrowed as `&EphemeralStore`, because calling `.get()` on the `ExternalPtr` resolves to extendr's `GetSexp::get` instead of Loro's method; watch for this with any Loro method named `get`.
- Detached editing (`set_detached_editing`) is a per-object runtime switch. While it is on, Loro assigns a fresh random peer id at every checkout and keeps it after re-attaching; edits made at an old version become a concurrent branch that merges on `doc_checkout(doc)`.
- Text positions can be converted between units with `LoroText::convert_pos` (`unicode`, `utf16`, and `utf8` map to `PosType::Unicode` / `Utf16` / `Bytes`). The R side keeps positions 1-based in every unit. A mid-character offset converts to the start of that character; only out-of-range offsets give `NA`.
- An explicit commit timestamp is stored even when timestamp recording is off, and Loro forces timestamps to be non-decreasing, so later commits without one inherit the latest stored value.
- `subscribe_first_commit_from_peer` fires only for local commits (once per peer id this document commits under), not for imported peers.
- Commit origins (`set_next_commit_origin`) are local labels: they reach subscribers as `event$origin` and are matched by prefix against an undo manager's excluded origins, but are not stored in history. Loro labels the commits made by undo and redo with origin `"undo"`.
- Undo is a plain `ExternalPtr<UndoManager>`; `undo` / `redo` return whether anything changed. Loro clears the undo and redo stacks on checkout.
- Sync extras in `lib.rs`: `loro_doc_export_impl` also handles `shallow_snapshot` (encoded frontiers in `since`); imports return an `ImportStatus` converted by `status_to_r` to column-wise `success` / `pending` ranges; JSON updates are serialized with `serde_json` (a direct dependency for that reason); JSONPath needs the `jsonpath` feature of the `loro` crate. `loro_doc_apply_diff_impl` computes the `DiffBatch` in a source document and applies it in the same call, so no diff object has to cross into R (the R list from `doc_diff()` is lossy: child containers appear by value).
- More Loro behaviors worked around: unparseable JSON passed to `import_json_updates` surfaces an unrelated "no active undo group" error, so the JSON is converted to a `JsonSchema` first and a clear error raised; `LoroList::pop` returns a child container as a bare id, so `loro_list_pop_impl` reads the deep value before deleting; `ensure_mergeable_*` on a key that already holds a mergeable container of another type silently creates a second container under the same key, so `loro_map_ensure_container_impl` checks the existing type first.
- `to_r_error` strips the ` Position: <source path>` suffix Loro appends to some error messages.
- Trees: node ids cross as `TreeID`'s display form (`"counter@peer"`), parsed back with `TreeID::try_from`; a root-level parent is `NULL` going in and `NA` coming out. Three Loro behaviors are worked around or documented. `LoroTree::children` returns `None` for a leaf as well as for a missing node, so `loro_tree_children_impl` checks existence itself. Loro allows a deleted node as the parent of a create or move (the node lands in the deleted part of the tree), which `to_live_parent` rejects. Undoing or reverting a node deletion recreates the subtree under new node ids.
- Positions in Rust are 0-based (text positions are Unicode code point indices via `LoroText::insert` / `delete` / `len_unicode`). Peer ids are `u64` and cross as decimal strings. Versions cross as `VersionVector::encode()` bytes.
- [src/rust/document.rs](src/rust/document.rs) is the `document` binary that regenerates [R/extendr-wrappers.R](R/extendr-wrappers.R) on every build. New functions must be listed in the `extendr_module!` block.

### R

- [R/doc.R](R/doc.R) defines the exported S7 class `loro_doc` (a `@ptr` slot holding the external pointer, so documents have reference semantics) and the `doc_*` functions: identity, fork, commit, deep value, path queries (`doc_get_path`, `doc_jsonpath`; both use Loro's 0-based list positions inside the path string), and sync (`doc_export` / `doc_import` / `doc_version`, JSON updates, `blob_metadata`). `doc_import` returns an import status invisibly, not the document.
- [R/container.R](R/container.R) defines the unexported S7 handle classes: abstract `loro_container` with children `loro_text`, `loro_map`, `loro_list`, `loro_counter`, and `loro_tree`, plus `loro_movable_list` as a child of `loro_list` (so every `list_*` function accepts it, while `list_move` / `list_set` / `list_set_container` require it). Users get handles from `doc_text()` / `doc_map()` / `doc_list()` / `doc_movable_list()` / `doc_counter()` / `doc_tree()` (root containers) or from a parent container; `container_from_ref` turns a Rust `creditor_container_ref` into the matching class and passes plain values through. Also holds `container_value()`, `container_id()`, and the shared print method.
- [R/text.R](R/text.R), [R/map.R](R/map.R), [R/list.R](R/list.R), [R/counter.R](R/counter.R), and [R/tree.R](R/tree.R) define the `text_*`, `map_*`, `list_*`, `counter_*`, and `tree_*` functions, each taking a handle as its first argument. The R API is 1-based; the conversion to 0-based happens here. Child containers are created empty by type name (`map_set_container`, `list_insert_container`, `list_push_container`) and returned as handles.
- [R/richtext.R](R/richtext.R) defines `text_mark` / `text_unmark` / `text_delta` / `text_apply_delta` and `doc_config_text_style`; `with_style_hint` rewrites Loro's missing-style error (which names the JS API) to point at `doc_config_text_style()`. [R/cursor.R](R/cursor.R) defines `text_cursor`, `list_cursor`, and `cursor_pos`; a cursor is a plain raw vector, like a version from `doc_version()`.
- [R/history.R](R/history.R) defines `doc_frontiers`, `doc_changes` (a data frame with a `frontiers` list column), `doc_change`, the counts, `doc_changed_containers`, the conversions between frontiers and version vectors, `doc_compare_frontiers`, `doc_checkout`, `doc_is_detached`, `doc_revert_to`, `doc_diff`, `doc_apply_diff`, and `doc_record_timestamps`.
- [R/events.R](R/events.R) holds the subscription registry (the `the` environment: id to `list(ptr, callback)`) and `deliver_events()`, which drains every registered queue and invokes callbacks, turning callback errors into warnings. Every exported function that can commit or import must call `deliver_events()` before returning (currently `doc_commit`, `doc_set_peer_id`, `doc_detach`, `doc_import`, `doc_import_json`, `doc_export`, `doc_export_json`, `doc_fork`, `doc_checkout`, `doc_revert_to`, `doc_diff`, `doc_apply_diff`, `undo`, `redo`, `undo_group`, and the mutating `ephemeral_*` functions); a function that misses it only delays delivery until the next one. The registry keeps a subscription alive until `unsubscribe()`.
- [R/ephemeral.R](R/ephemeral.R) defines the `ephemeral_*` functions. Loro's Rust API does not expire entries on a timer (the JS wrapper does), so expiry is only applied when `ephemeral_remove_outdated()` is called. Entries are last-write-wins on a millisecond timestamp, and a receiving store drops a write that is not strictly newer, so two writes to one key in the same millisecond leave receivers stale; tests that sync successive writes to one key must sleep between them (`tick()` in `test-ephemeral.R`).
- [R/undo.R](R/undo.R) defines `doc_undo_manager`, `undo`, `redo`, `can_undo`, `can_redo`, the step counts, `undo_group`, pause and resume, and `undo_clear`.
- [R/utils.R](R/utils.R) holds the argument checks (`cli::cli_abort()`).
- Mutating functions return their first argument invisibly, except the `*_container` creators, which return the new handle.

## Toolchain

- Rust edition 2024, rustc >= 1.85 (declared in `DESCRIPTION` via `SystemRequirements`). Bridge: `extendr-api` 0.9.
- Crates are fetched by cargo at build time (no vendoring; not CRAN-targeted). `src/rust/Cargo.lock` is committed.
- Rebuild after Rust edits with `devtools::document()`; set the `DEBUG=1` environment variable for a fast unoptimized build (the release profile uses LTO and is slow).
- [tools/config.R](tools/config.R) and [tools/msrv.R](tools/msrv.R) run at install time from `configure` to check the toolchain and template `src/Makevars{,.win}.in`. They are rextendr-generated; do not restyle or remove them.

## Style

- R: use `=` for assignment, `pkg::fn` over imports, minimize single-line comments.
- Rust: standard rustfmt; no decorative comments.
- Commit messages: one short imperative line, no attribution trailers.
